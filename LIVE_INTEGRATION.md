# FretShift live integration runbook

This runbook is for the hosted Supabase/OCR stage only. Keep real credentials out of Git.

## 1. Link the hosted Supabase project

Install/login to the Supabase CLI, then link the project you intend to use:

```sh
supabase link --project-ref "$SUPABASE_PROJECT_REF"
```

Before applying anything, inspect the pending migration:

```sh
supabase db push --dry-run
```

If the dry run shows only the expected FretShift migration, apply it:

```sh
supabase db push
```

## 2. Configure Auth redirects

In Supabase Auth URL Configuration:

- Set the Site URL to the production HTTPS origin once it exists.
- Allow the exact production `${origin}/settings` callback.
- During local verification, also allow `http://127.0.0.1:5173/settings` (and `http://localhost:5173/settings` if that origin is used).

FretShift supports both an 8-digit email verification code and a magic link. Both are generated by Supabase passwordless email Auth; the hosted Magic link / OTP template should include both `{{ .Token }}` and `{{ .ConfirmationURL }}`. The code path verifies inside the same browser/PWA and is the recommended iPhone flow. Magic links continue to use `${location.origin}/settings` as the redirect.

## 3. Configure and deploy the vision function

Set server-only secrets. `ALLOWED_ORIGINS` may contain a comma-separated list.

```sh
supabase secrets set \
  OCR_SPACE_API_KEY='...' \
  ALLOWED_ORIGINS='http://127.0.0.1:5173,https://your-production-origin.example'
```

Deploy:

```sh
supabase functions deploy vision-import --use-api
```

`supabase/config.toml` intentionally sets `verify_jwt = false` for `vision-import`. The function itself verifies the caller's bearer session against Supabase Auth, avoiding the legacy platform JWT gate while still requiring a valid signed-in user.

## 4. Configure the client

Create `.env.local` (ignored by Git):

```sh
VITE_SUPABASE_URL=https://YOUR_PROJECT.supabase.co
VITE_SUPABASE_PUBLISHABLE_KEY=YOUR_PUBLIC_KEY
```

Existing projects may keep using `VITE_SUPABASE_ANON_KEY`; FretShift supports both.

## 5. Run the non-destructive live smoke test

With the public variables exported in the shell:

```sh
pnpm verify:live
```

This verifies Auth reachability, the public share RPC, and vision CORS. It creates no sync/share records and makes no OCR.space request.

For the signed-in checks, set `FRETSHIFT_USER_ACCESS_TOKEN` to a FretShift user-session access token and run the same command. Do **not** use the Supabase CLI personal access token for this variable. The signed-in probe checks the sync table, performs a compare-and-swap miss that cannot create a row, and sends an invalid vision body that stops before OCR.space.

## 6. Real user-path verification

After the smoke test is green:

1. Start FretShift and request a verification code from Settings; enter the six digits in the same app and confirm the library sync starts. Then separately smoke-test the optional magic-link path.
2. Open the link and confirm the account becomes signed in.
3. Make a small song edit, wait for sync, reload, and confirm it remains.
4. Open the same account on a second device/browser profile and confirm the song arrives.
5. Create a public song link, open it signed out, save a local copy, then revoke the link and confirm it stops resolving.
6. Import one real chart photo and one scanned PDF. Review the draft before saving.
7. Only after real photos are added to the benchmark corpus, run `pnpm bench:vision` and record the observed chord accuracy / lyric CER.

Do not mark SMTP, cross-device behavior, OCR accuracy, provider retention, or hardware checks complete until they have been observed on the real services/devices.
