## Datasets and scoring

**Real audio.** Four mono microphone recordings, 93.156 seconds total, from [GuitarSet v1.1.0](https://zenodo.org/records/3371780) (Xi, Bittner, Ye, Pauwels, Bello), mirrored at [`jhartquist/guitarset`](https://huggingface.co/datasets/jhartquist/guitarset), CC BY 4.0. Exact WAVs, row IDs, author/license attribution, original chord/beat labels, and SHA-256 hashes are in `test-fixtures/audio-intelligence/guitarset/`. The clips are acoustic composition performances by **one player**: bossa nova, funk, and two jazz tempos. They are real guitar audio with independently supplied labels. Their complex chord symbols are kept intact. Exact chord scoring uses only directly representable, unmodified reference labels (mean eligible fraction 47.42%); root scoring includes all labeled chord time. No training or tuning on these clips was done. The mirror's row-level labels were accepted as provided, not independently hand-audited against listening.

**Synthetic audio.** The retained 11 deterministic generated PCM fixtures cover acoustic-like, clean-electric-like, distorted, vocal-like, full-band-like, repeated/extended chords, silence, noise, melody, and tempo ramp. These are **not recordings of those instruments or a real ensemble**. A generator-provided guitar-only channel is an oracle diagnostic, not a deployed separator. Source results remain in `AUDIO_INTELLIGENCE_PHASE_1_BENCHMARK_RESULTS.json`; this pass reran the same fixture definitions into `AUDIO_INTELLIGENCE_BENCHMARK_RESULTS.json`.

`pnpm bench:audio-real` verifies WAV hashes and scores the existing local analyzer via Vite SSR. Chord root precision/recall is based on 50 ms reference-labeled time samples. A wrong root counts against both precision and recall; an unlabeled prediction counts against recall. Exact chord metrics are separate and restricted to eligible reference time. Segment IoU is the best overlapping **root-matched** predicted segment for each reference segment, averaged per case. Beat and change precision/recall use one-to-one matches within 70 ms and 250 ms respectively. Predicted chord changes compare successive recognized labels; entering or leaving an unlabeled region is counted as uncertain coverage, not as a false chord change. Summary means are unweighted means of the four case values. This benchmark measures core analysis after PCM loading; it excludes browser decode, UI rendering, network, and user review time.

## Hardening performed

1. **Silent merge loss:** `mergeRegion()` previously retained the first chord while discarding a different next chord. It now rejects a merge unless labels match; distinct Unknown and No chord decisions also cannot be merged. Merging matching null-label regions preserves Unknown, No chord, or unresolved state. Unit coverage checks rejection and state preservation.
2. **Silent late-chord loss:** `reviewedAnalysisToSong()` previously skipped a chord whose quantized position fell beyond the chart's beat grid. It now asks for beat-grid correction instead of silently dropping the attack. A unit test reproduces it.
3. **Wrong source reattachment:** Phase 2 accepted any same-named file. New saves include a SHA-256 source fingerprint in optional `provenance.audioReview.fileSha256`; reattachment checks it before playback. Existing saved Songs remain schema-valid and receive an explicit older-recording warning. Browser coverage tries a different same-named file, then the correct file. Stale fingerprint completions cannot attach audio after navigation or a newer selection. Hashing adds a whole-file browser read and has not been peak-memory profiled.
4. **Large uncertain timelines:** The review shows how many unlabeled regions require a decision and offers an explicit bulk **Mark all uncertain regions Unknown** action. This preserves uncertainty and avoids asking a player to open hundreds of unlabeled blocks one by one. Browser coverage performs this edit while the network is offline after analysis.
5. **Normal-user copy:** The primary panel now says the recording stays on the device, shows simple timing/chord review language, and places Worker/storage and classifier explanations under **Advanced**.
6. **Mobile waveform cropping and seeking:** The 512 waveform bars had a 1 px minimum width plus 1 px gaps; on a 390 px viewport the final bar extended to x=1065 while the track ended near x=348. Hidden overflow cropped most of the recording. Bars now shrink to fit the full timeline. Seeking now measures pointer position relative to the entire track, rather than a clicked child bar. The strengthened browser test checks the waveform before navigation and verifies a click at 75% seeks to about 3 s in a 4 s clip. Desktop/mobile screenshots are in `docs/audio-validation/`.

No trained recognizer, separator, tab provider, server job, Supabase migration, or new dependency was introduced. `supabase/functions/vision-import/index.ts` was not edited; its SHA-256 remains `2290ede345a50dc10b291c9519aee484f5d597050156790dd3f0883c82cb01dc`.

## Verification and reliability scope

Final verification on September 26 is backed by raw JSON: 271/271 unit tests, 12/12 browser cases, then 4/4 targeted upload/mobile checks after the waveform fix. Screenshots of desktop and 390 px review layouts were captured in both engines; Chrome mobile and WebKit desktop were visually inspected for wrapping and full-waveform display. The complete 12-case group was not repeated after the final CSS/seek fix; its two affected flows were rerun in both engines. `AUDIO_INTELLIGENCE_BUILD_LOG.txt` records the final lint/build gate.

On Node 26.7.0 with `NODE_OPTIONS=--no-experimental-webstorage`, the full Vitest suite passed 271/271; 14 audio-specific tests passed within the full suite. ESLint plus TypeScript passed, and the production Vite build passed. The expanded Playwright audio suite passed **12/12** across installed Chrome and Playwright WebKit (six cases each): WAV/MP3/M4A decode and Worker analysis, upload/review/save/reload/Immersive entry, pre-aborted cancellation/retry, same-name fingerprint rejection, oversized 30 MB rejection, real-acoustic review edit after network loss, 390 px viewport and object-URL cleanup, and unconfirmed-timing Practice guard. The Immersive beta-gate verification script passed. These are desktop browser and simulated narrow-viewport checks, **not physical iPhone Safari, installed PWA, or Android device tests**. The file-selection test uses browser file injection; no system file-picker automation was performed.

Audio Intelligence uses no server audio job, upload, GPU, queue, or external model. Therefore server job authentication, temporary-upload expiry, rate limiting, server cancellation, cold start, concurrency and server compute pricing are not applicable to this implementation. The UI permits one analysis at a time, a Worker is terminated on completion/abort, and the object URL is revoked on replacement/unmount. Web Audio decoding cannot be interrupted mid-decode; the UI waits for cleanup before retry. `onStage` reports named steps, not invented percentages. The normal authenticated Song sync system may sync derived metadata; live two-account isolation was **not tested**. Raw audio was not saved by this feature.

Not tested: physical iPhone Safari/PWA, Android Chrome, Safari desktop app rather than Playwright WebKit, backgrounding, screen lock, low-memory termination, a five-minute recording at the limit, an interrupted cloud sync, cross-account isolation, live provider/remote deployment, vocals or full band in real audio, multiple real guitars, distorted/clean electric real recordings, modulation, tempo changes, triplets, and note/polyphonic transcription. Browser offline review was tested after the clip had already loaded and analyzed; offline first-load or offline analysis was not established.
